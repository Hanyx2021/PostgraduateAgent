# 架构说明

本文说明五步流水线在代码里的落点，以及每个环节"为什么这样切"。

## 数据流

```
                    ┌──────────────────────────────┐
学生材料 ──────────► │ ingest/   解析为纯文本 + 定位  │ ──► ParsedDocument
（简历/论文）        └──────────────┬───────────────┘
                                   │ 模型抽取（prompts.EXTRACTION）
                                   ▼
                    ┌──────────────────────────────┐
                    │ ledger/   引文回查原文，编造即弃│ ──► LedgerRecord[]（id: L-0001）
                    └──────────────┬───────────────┘
                                   │
导师库 ◄── 抓取（guards.injection 标记不可信）
   │                               │
   ▼                               ▼
┌──────────────┐          ┌──────────────────┐
│ retrieval/   │─────────►│ ranking/         │
│ BM25 + 向量  │  Top-30  │ 逐对判断 + 证据校验│ ──► MatchResult（三档）
└──────────────┘          └────────┬─────────┘
                                   │ 学生选择导师
                                   ▼
                          ┌──────────────────┐
                          │ email/  四段式草稿│ ──► EmailDraft（status=draft）
                          └────────┬─────────┘
                                   │ validate_draft：无据句整段丢弃
                                   ▼
                          ┌──────────────────┐
                          │ confirm/ 逐句确认 │ ──► ConfirmationRecord
                          └──────────────────┘
                                   │
                                   ▼
                          学生复制到自己邮箱（系统无发信能力）
```

## 模块职责与边界

| 模块 | 输入 → 输出 | 关键约束 |
| --- | --- | --- |
| `ingest/` | 文件 → `ParsedDocument` | 解析失败返回 None，不猜；抓取内容视为不可信 |
| `ledger/build.py` | 抽取结果 + 原文 → `LedgerRecord[]` | `quote_is_grounded` 做原文包含检查，找不到就丢 |
| `retrieval/` | 画像 → `Advisor[]`（30 位） | 检索文本不含姓名、院系、职称 |
| `ranking/rerank.py` | 学生 × 导师 → `AdvisorMatch` | 每条判断必须双向有据；默认规则版，LLM 版引文必须来自给定 sources，失败自动退回规则版 |
| `ranking/tiers.py` | `AdvisorMatch[]` → `MatchResult` | 无总分；档内排序确定性；保留探索位 |
| `email/draft.py` | 匹配 + 台账 → `EmailDraft` | 只接受学生自写的要点，不新增事实 |
| `email/validator.py` | 草稿 + 台账 → 草稿′ + 报告 | 无据句整段丢弃；寒暄句白名单 |
| `email/confirm.py` | 草稿 → 留痕记录 | 无 send；全部确认才可标记 confirmed |
| `guards/` | 各环节调用 | 敏感字段、注入、收件人三重检查 |

## 为什么台账是主干

匹配理由和邮件句子都要引用 `L-xxxx`。这意味着：

- 匹配阶段无法编造"研究方向高度契合"，因为模型必须给出学生侧台账 ID；
- 邮件阶段无法把"在投"写成"已发表"，因为句子要绑到状态字段明确的记录上；
- 评估阶段可以自动统计"无据陈述占比"，而不需要人工读每一封信。

如果后续要做新的功能（比如面试准备清单），也应当从台账出发，而不是新开一条生成链路。

## 评估口径

| 指标 | 定义 | 位置 |
| --- | --- | --- |
| Recall@10 / nDCG@10 | 合成画像（2027 目录方向 → 在列导师）为真值，基线为主表顺序与随机 | `evaluation.py`（双盲标注与大模型基线待补） |
| 无据陈述占比 | 交付草稿中 `ledger_refs` 无法解析的句子比例，必须为 0 | `ValidationReport` |
| 反事实一致性 | 仅改身份信息后 `MatchResult.model_dump()` 完全一致 | `tests/test_fairness.py` |
| 注入越权数 | 20 条样本触发越权行为的次数，必须为 0 | `tests/test_injection.py` |

### 分专业结果与权重网格（30 个合成画像，k=10）

| 专业代码 | 画像数 | Recall@10 | nDCG@10 |
| --- | ---: | ---: | ---: |
| 081200 计算机科学与技术 | 25 | 0.530 | 0.519 |
| 140500 智能科学与技术 | 4 | 0.152 | 0.223 |
| 083500 软件工程 | 1 | 0.000 | 0.000 |

权重网格（BM25 / 向量）：0.0/1.0 → 0.443/0.432；**0.3/0.7 → 0.462/0.462**；
0.5/0.5 → 0.455/0.441；0.7/0.3 → 0.457/0.408；1.0/0.0 → 0.434/0.387。
默认权重已按网格结果改为 0.3/0.7。样本只有 30 个画像，换数据后应重新校准。

最差的五个方向：传感器网络与物联网、信息系统工程、智能基础理论、可信计算与系统性能评价、
生物信息学。共同点是目录方向名与导师研究标签/论文词汇差异大，或真值导师未进入索引。

### 重排策略对比（10 个画像，k=10，最终推荐列表）

| 策略 | Recall@10 | nDCG@10 |
| --- | ---: | ---: |
| 规则版 | **0.301** | 0.311 |
| 模型版（收紧后：单条引文、最多 2 条、拒绝宽泛类比） | 0.281 | **0.326** |
| 混合版（规则证据全保留，模型只补充） | 0.300 | 0.320 |

模型版覆盖面更大，但在"2027 目录方向"这个真值上，前 10 位的召回仍低于规则版：
模型会把语义相关、但不在该目录方向上的导师也放进推荐，稀释了命中。
收紧提示词后（引文必须是单个方向/tag、最多两条、拒绝"都涉及检索"式类比），
模型版 nDCG 从 0.280 提升到 0.326，超过规则版；Recall 停在 0.281。这是"更严格=更准
但更窄"的取舍。

混合版把规则证据全部保留、模型只做同档补充，并用"规则证据优先"排序：
Recall 0.300 与规则版基本持平，nDCG 0.320 高于规则版。因此界面开启模型重排时
使用混合模式；不开模型时仍是纯规则版。真值口径本身偏向规则版，结论需配合人工标注复核。

### 当前结果（30 个合成画像，k=10）

| 系统 | Recall@10 | nDCG@10 |
| --- | --- | --- |
| 混合召回（BM25 0.3 + 向量 0.7） | **0.462** | **0.462** |
| 纯向量召回（BGE-small-zh） | 0.443 | 0.432 |
| 纯 BM25 | 0.434 | 0.387 |
| 主表顺序基线 | 0.141 | 0.109 |
| 随机基线 | 0.100 | 0.059 |

补论文后 98.4% 的真值导师能进入索引（原来 78.7%，缺研究标签的导师靠论文标题
补上了一部分），混合召回 0.462 约为可达上限的 47%。向量召回把"人工智能 vs
机器学习"这类词汇差异补回了一部分。论文只收标题、不收摘要：对照实验中摘要会把
中文方向匹配稀释得更厉害（Recall 0.468 → 0.453），标题则能提升 nDCG（0.437 → 0.445）。

把目录方向直接写进索引可以显著提高数字，但那会让真值与特征同源，评估失去意义，
所以刻意没有这样做。

向量模型是本地 BGE-small-zh（约 95MB，ModelScope 下载，`data/models/` 不入库）；
没有模型时自动退回 BM25，不影响主流程。

## 尚未确定的选型

- 向量模型：本地 sentence-transformers 还是 API embedding —— 取决于"脱敏后调用"能否满足；
- 向量库：中期前先用 numpy 矩阵，规模到千级再考虑 faiss；
- 模型供应商：需确认内容不用于训练，见 `.env.example` 的注释；重排已提供 LLM 接口，
  默认仍是可复现的规则版。实测 30 位候选串行调用约 446 秒，因此界面只对召回前
  `llm_rerank_top`（默认 10）位调用模型，其余走规则版；并发 4 路冷启动约 47 秒，
  命中本地缓存后约 2 秒（缓存只存返回文本，目录 `data/cache/`，可随时删除）；
- 论文来源：OpenAlex（作者 ID + 机构核验，60/70 已补全）。其中 8 位人工指定作者 ID，
  2 位因 OpenAlex 记录合并、改用官方主页题录（陈挺、徐昆）；刘卫东暂无可核验的近期
  论文；9 位按"基本不招生"排除。只保留 Computer Science 领域的作品，避免同名记录
  混入化学/医学论文。
